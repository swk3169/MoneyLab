# ECON-SCREEN-V06-01 사전등록: Upbit KRW-BTC 일 단위 long/cash 4전략의 비용 후 경제성 선별 (탐색)

상태: 사용자가 승인한 바이트로 최초 고정 커밋이 완료되는 시점에 효력이 생긴다. 그 전에는 후보이며 어떤 권한도 만들지 않는다.
판: v1. 증거 등급: L1_SCREENING / NOT_CONFIRMATORY.

## 0 지위와 관계

- 이 study는 v0.6 사전등록 초안(DRAFT)과 별개의 탐색적 선별이다. v0.6 초안, 고정된 다른 연구, 그 판정·보류·노출 기록을 바꾸지 않는다.
- 이 문서의 품질 해석(5절)은 이 선별에만 적용한다. v0.6 본 연구의 Q 기준을 확정하거나 바꾸지 않는다.
- V0 무익성 검정, 통계적 채택, 공식 REJECT, p값, 검정 통계는 계산하지 않는다. 결과는 기대수익의 입증, 통계적 실패 증거, 실거래 적합성 판단이 아니다.

## 1 목적

비용 후 순수익의 기술적 관측으로, 별도 확증 연구에 자원을 쓸 후보가 있는지 판단할 근거를 만든다.

## 2 대상

- primary 4개 M20, M60, M120, R5. 정의는 v0.6 초안 6.1이며 구현은 backtest의 PREREG_V06_RULES다. 네 전략을 모두 평가하고 보고한다. secondary는 제외한다. 시도 수는 4다.
- M60과 M120은 사전 관심으로만 적으며, 평가 대상과 보고 범위를 바꾸지 않는다.

## 3 데이터와 구간

- 시장: Upbit KRW-BTC 공개 REST 캔들, 일봉과 1시간봉, provenance real.
- 요청 범위: requested_start = 2017-01-01T00:00:00Z, requested_end = 2024-04-01T00:00:00Z(배타).
  - requested_start는 요청 하한이며 상장일을 뜻하지 않는다.
  - 수집기는 requested_end부터 과거 방향으로 페이지를 요청한다. 빈 페이지를 받거나 가장 이른 캔들이 requested_start 이하가 되면 멈춘다. 빈 페이지를 과거의 끝으로 보는 것은 수집기 코드의 규칙이며 API 동작으로 검증되지 않았다(수집기 경고 "treated as earliest available (unverified)").
- 범위 밖 응답: start_utc가 [requested_start, requested_end) 밖인 캔들이 응답에 들어오면 원본 페이지에는 남지만, Bar 변환·품질·평가에 쓰지 않는다. 그 개수(excluded_out_of_range)를 보고하고, 2024-04-01 이후 bucket이 들어온 경우 그 사실을 노출 기록 후보로 보고한다. 이 경우 내용은 열지 않는다.
- 수집 진행 조건: 다음이 모두 성립할 때만 진행한다. 하나라도 아니면 "수집 범위 미확정"으로 STOP한다. 이 조건의 충족은 거래소 전체 이력의 완전성이나 누락 부재를 증명하지 않는다. 빈 페이지 종료와 두 interval 첫 날짜 일치의 의미는 API 수준에서 검증되지 않았다.
  - 두 pull 모두 status complete, 페이지 상한 오류 없음, candles-verify ok
  - 두 pull 모두 reached_earliest = true(빈 페이지로 종료)
  - 1시간봉 첫 bucket의 날짜(UTC)가 일봉 첫 bucket의 날짜와 같음
- d0: 검증된 첫 확정 일봉의 시작일(UTC 00:00). 데이터로 정해지며 상장일로 주장하지 않는다.
- warmup: d0부터 d0 + 119일까지는 신호 계산에만 쓴다.
- 첫 신호일 F = d0 + 120일, 마지막 신호일 E = 2024-03-29.
- 평가 구간 G = [F + 2일, E + 3일) = [d0 + 122일, 2024-04-01T00:00:00Z).
  - 세 시나리오의 가상 청산 기준 시각은 모두 G 끝 이하다: E0 2024-03-31T01:00Z, E1 2024-03-31T02:00Z, E2 2024-04-01T00:00Z.
  - 엔진은 G 끝보다 늦게 끝나는 bar를 체결·평가에 쓰면 실패한다.
- 노출: 평가 구간 가격은 AI 학습 데이터와 연구자 지식으로 이미 알려진 가격이다(L1). 2024-04-01 이후 구간을 미열람·무오염이라고 하지 않는다. 기존 노출 기록과 v0.6 holdout·forward 규칙은 그대로 둔다.

## 4 비용, 체결, 자본

- 시나리오: E0(기준), E1, E2. backtest.execution의 SCENARIOS 정의를 그대로 쓴다. E3와 DIAG는 계산하지 않는다.
- 편도 수수료 f ∈ {0, 5, 15, 25} bp, fee_basis inclusive. 0 bp는 진단용이다. 계정 수수료가 확인되지 않았으므로 기준은 25 bp다.
- spread·slippage κ: 시나리오 표(E0 5 bp, E1 10 bp, E2 10 bp).
- 시장 충격 ι(C) = 1.0 bp × √(C / 1,000,000), C ∈ {1,000,000, 5,000,000, 10,000,000} KRW(가정).
- 기준 조합: E0, 25 bp, C = 10,000,000 KRW.
- 전체 조합: 4 전략 × 3 시나리오 × 4 수수료 × 3 자본 = 144. 모두 계산·보고한다.
- 체결 대체는 v0.6 초안 6.3 규칙(fill_substitution = prereg_6_3), 가상 청산은 8.1 규칙이다.

## 5 품질 (계산 진입 조건)

- 상태 값은 PASS, INVALID, NOT_EVALUATED 셋이다. 묶음 상태는 하나라도 INVALID면 INVALID, 아니면 INCOMPLETE이며, VALID는 쓰지 않는다. 공식 Q = VALID는 이 study의 범위가 아니다.
- 필수 검사 중 하나라도 INVALID 또는 NOT_EVALUATED면, 수익률을 계산하거나 열람하기 전에 STOP한다.
- 순서:
  1. 원본 무결성: candles-verify(Q1)
  2. Q6: pull 품질 보고서로 판정
  3. 수집 진행 조건(3절)
  4. 검증된 Bar 변환(이 study 전용 경로)
  5. Bar 기반 Q2, Q3, Q4, Q7
  6. 경제성 계산
  - Bar 변환 전에 Bar 기반 검사를 요구하지 않는다.
- Q1: 두 pull의 candles-verify가 ok면 PASS.
- Q6: 두 pull의 보고서에서 값이 다른 중복(duplicates_conflicting)이 0이고 값 이상(invalid)이 0이면 PASS다. 1건 이상이면 INVALID다(이 study의 규칙이며 v0.6 초안의 0.1 % 기준보다 엄격하다). 같은 값 중복의 개수는 보고만 한다.
- Q2(일봉)와 Q3(1시간봉):
  - 기대 bucket: [d0 00:00, 2024-04-01T00:00Z) 안의 모든 bucket
  - 누락 수 = 기대 bucket 수 − 존재하는 고유 bucket 수. 분모는 기대 bucket 수다.
  - 기준: Q2 ≤ 1/200, Q3 ≤ 1/100. 비율은 정확 분수로 비교한다.
  - 임계값 0.5배와 2배의 결과를 함께 보고한다(보고 전용).
- Q4:
  - gap_event: 일봉 연속 누락 3 bucket 이상, 또는 1시간봉 연속 누락 7 bucket 이상
  - 누락 구간이 G와 하나라도 겹치면 센다. 공백 길이는 G로 자르지 않는다.
  - 일봉과 1시간봉 건수의 합이 3 이상이면 INVALID다.
- Q7:
  - 비교 가능일: d0 이상 2024-03-31 이하의 날 D 중, 일봉 D와 [D 00:00, D+1 00:00)의 1시간봉 24개가 모두 있는 날
  - 불일치일: 시가 ≠ 첫 1시간봉 시가, 종가 ≠ 마지막 1시간봉 종가, 고가 ≠ 1시간봉 최대 고가, 저가 ≠ 1시간봉 최소 저가, 거래량 ≠ 1시간봉 거래량 합 중 하나라도 해당하는 날. Decimal 정확 일치로 비교한다.
  - 정확 일치는 이 study의 개발 규칙이며, 실데이터 허용 오차가 검증됐다는 뜻이 아니다.
  - 기준: 불일치일 ≤ 비교 가능일의 1/200. 비교 가능일이 0이면 NOT_EVALUATED.
- 보고만 하는 검사: 계산 뒤 Q9·Q10 영향 건수(신호 None 일수, 체결 대체·가상 대체 건수).
- NOT_EVALUATED로 표시하는 검사(계산 진입 필수 아님): Q5, Q8, Q11(구간 밖), Q12(재수집 없음), Q13.

## 6 표본 조건

- 출처: v0.6 초안 11.1의 기존 규칙(확증 평가 기간 5년 이상, 왕복 20회 이상)을 이 선별에 그대로 쓴다.
- 평가 기간: G의 길이가 5 × 365일 이상이어야 한다. 아니면 모든 전략이 SCREEN_NOT_EVALUABLE다.
- 왕복: 기준 조합(E0, 25 bp, 10,000,000 KRW)에서 가상 청산을 포함한 왕복이 20회 이상이어야 한다. 아니면 그 전략의 모든 조합이 SCREEN_NOT_EVALUABLE다.
- 이 조건은 기술적 선별의 표본 조건이며, 검정력이나 통계적 충분성을 보장하지 않는다.

## 7 비교 기준

- B2 보유(진입·청산 각 1회 비용), B3 현금, B4 노출을 맞춘 보유(보고 전용), B1 같은 노출의 무작위 배치.
- 모든 비교 기준은 전략과 같은 기준 시각, 시장 수익률, 비용(진입 c_b, 청산 c_s, 마지막 날 가상 청산)으로 평가한다(backtest.benchmarks).
- B1:
  - 생성 규칙: benchmarks.b1_positions(보유 구간 길이와 내부 현금 구간을 각각 섞고, 앞뒤 현금 일수를 무작위로 나눔)
  - 반복 9,999회. seed = 20261119, 규칙 bt-seed/1, label = ["B1", 전략, 시나리오]
  - label에 수수료와 자본이 없으므로, 같은 전략·시나리오의 12개 비용 조합은 같은 무작위 배치를 공유한다. 비용 효과는 같은 배치에서 비교된다.
  - 보고: B1 평균 로그수익률, q05, q50, q95(선형 보간, h = (K − 1) q), 전략 평균 − B1 평균
  - 원장 정렬(alignment)이 성립하지 않는 조합은 비교하지 않고 not_aligned 사유를 보고한다.
- 계산량(자원 계획용 산술, 측정값 아님): B1 비교 144회 × 9,999회 × 평가 일수(약 2,200–2,300일)이며, 원소 반복은 수십억 회 규모다. 이 값은 실행 시간·자원을 보장하지 않으며, 자원 측정과 예산 승인은 12절을 따른다.

## 8 보고 정의

- 일별 순수익 r_t: 모든 비용 뒤 일별 로그수익률. 마지막 날은 가상 청산 뒤 값이다.
- 연환산 순수익 = 365 × 평균 r_t. 누적 = exp(Σ r_t) − 1.
- 왕복: 가상 청산 포함 보기를 기본으로 하고, 완료분만 보기를 함께 보고한다. 연간 왕복 = 왕복 수 / (평가 일수 / 365).
- 손익분기 수수료 f*: backtest.cost_analysis.break_even_fee(κ·ι·체결 고정, inclusive). 왕복이 0이면 계산 불가로 보고한다.
- MDD: backtest.performance.max_drawdown_log(P 기준).
- 회복 기간: MDD 저점일부터 자산이 직전 고점 이상이 되는 첫날까지의 일수. 평가 끝까지 회복하지 못하면 "미회복"이다. 이 정의는 이 study에서 새로 구현한다.
- 연도별: UTC 연도별 순수익과, 완전한 연도만으로 센 양(+)의 연도 비율(backtest.yearly).
- 그 밖: 노출 비율, 연간 비용 부담, gross/비용 비율, Q9·Q10 영향 건수.
- 계산 불가 값은 사유와 함께 보고하며, 0이나 다른 값으로 바꾸지 않는다.

## 9 선별 표시 (사전 고정, 판정 아님)

- SCREEN_FLAG_PASS: 다음이 모두 성립.
  - 기준 조합에서 순 평균 > 0
  - 기준 조합에서 순 평균 > B1 평균
  - E1과 E2(25 bp, 10,000,000 KRW)에서도 순 평균 > 0
  - 기준 조합에서 양(+)의 연도 비율 ≥ 0.60
- SCREEN_FLAG_NOT_MET: 위 조건 중 하나라도 성립하지 않음.
- SCREEN_NOT_EVALUABLE: 품질·표본 조건 미충족, 또는 기준 조합의 B1 비교가 not_aligned.
- 4개 전략의 표시와 144개 조합 전체를 함께 보고한다. 표시는 후속 확증 연구 후보로 검토할 가치 이상을 뜻하지 않으며, 수익성 입증이 아니다.

## 10 잠금과 승격 금지

- 수집 요청의 끝은 배타 2024-04-01T00:00:00Z다. dry-run으로 먼저 확인한다.

## 12 자원과 승인 경계

- 구현 검증 단계에서 실제 데이터 없이 합성 입력만 사용하는 제한된 자원 측정을 할 수 있다. 측정 규모·횟수·시간·메모리 한도는 후속 구현 계약에서 사전에 정한다.
- 실제 선별 데이터나 결과를 보고 계산 예산을 조정하지 않는다.
- 실제 선별 실행 전에 시간·메모리·worker 수·중단 기준을 승인받는다.
- 선별 실행 승인과 결과 내용 열람 승인은 별개다. 같은 메시지에서 둘을 승인하려면 두 범위를 각각 적어야 한다.
- 계산 종료 뒤의 무결성 확인(파일 집합, 해시, 운영 기록)과 결과 내용 열람을 구분한다. 무결성 확인은 결과 내용을 열지 않는다.
- 자원 부족이나 실패 뒤 자동 재실행은 하지 않는다.
